## Why

Sessions 2 and 3 shipped identity and reference data, but a volunteer still has no profile surface: after registering they can read nothing about themselves, tag no skills, declare no availability, and see no dashboard. Everything downstream — accepting applications (S7), publishing experiences (S11), public discovery (S12) — reads `volunteer_profiles`, so this change constructs the volunteer's private profile area and the privacy flags the public session will honor.

## What Changes

- Add `volunteer_profiles`, `volunteer_skills`, `volunteer_availability` models with the inventory §3 indexes: unique `userId`, unique `username`, unique `(volunteerId, skillId)`, unique `volunteerId`, plus `location.municipalityId` and `publicProfile.enabled` support.
- Add all `§2.5` routes under `/api/v1/volunteers/me(...)`: `GET/PATCH /volunteers/me`, `PATCH /volunteers/me/public-settings`, `GET /volunteers/me/dashboard`, skills CRUD (`GET/POST /volunteers/me/skills`, `PATCH/DELETE /volunteers/me/skills/:skillId`), and `GET/PUT /volunteers/me/availability`. Owner-only via the resolved account (inventory §6).
- Complete the S2 `RegistrationExtrasService` seam: a `VolunteerRegistrationExtrasService` provider bound to `REGISTRATION_EXTRAS_SERVICE` in `src/common/common.module.ts`, dispatching on `user.role` — for `volunteer` it creates the `volunteer_profiles` row with a username generated by the S3 slug util (`createWithUniqueSlug`); for every other role it delegates to `InertRegistrationExtrasService`. No non-volunteer behavior changes (parallel-merge rule).
- `avatar`/`banner` accept `mediaId` validated **only** as a well-formed Mongo ObjectId now; existence/ownership land in Session 8 (F9). No `media` model or collection check is added.
- Public-read seams (inert but consumed by S12): `getPublicProfile`, `listPublicTalents`, `getPublicExperiences` return correct empty shapes and enforce the A5 `404 when publicProfile.enabled=false` contract; `getPublicPortfolio` stays the Session 1 `PortfolioQueryService` default (inert until S14). The portfolio seam is not replaced.
- Profile completion % computed by `VolunteersService`; dashboard reads `volunteer_profiles.stats` (zeros until S11) and returns an empty latest verified experience placeholder.

## Capabilities

### New Capabilities
- `volunteers`: the volunteer's private profile area — `volunteer_profiles`/`volunteer_skills`/`volunteer_availability` collections, `/volunteers/me` profile read/update, `public-settings` privacy toggles, skills CRUD, whole-schedule availability replace, completion-% dashboard, and the A5 privacy-flags shape on the profile.

### Modified Capabilities
- `extension-seams`: `RegistrationExtrasService` gains a real volunteer provider (role-dispatched, delegating to the inert default otherwise); the public-read seams `getPublicProfile`, `listPublicTalents`, `getPublicExperiences` are named with the A5 flag/404 contract (inert now).

## Impact

- New module tree in `/backend/src/volunteers`; volunteer provider in `/backend/src/volunteers` plus seam wiring in `/backend/src/common/common.module.ts`.
- New collections: `volunteer_profiles`, `volunteer_skills`, `volunteer_availability`.
- New routes: the eleven `§2.5` routes listed above, all `Vol`-gated.
- No new packages or env vars.
- Out of scope: public endpoints (S12), media storage (S8), stats computation (S11), portfolio (S14).
